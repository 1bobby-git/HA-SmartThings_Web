# 밝기 재요청 및 상태 확인 — 1.8.21

1.8.20 배포 패키지 자체에는 소스 누락이 없었습니다. 후속 코드 검토에서 개별 `setLevel` 및 검증된 Web `setNumber`→`setLevel` 경로는 저장된 값이 요청값과 같으면 실제 기기를 읽지 않고 명령을 생략하는 조건이 남아 있었습니다. 예를 들어 HA/Bridge 캐시는 3인데 실물 밝기가 외부 조작으로 80으로 바뀌고 이벤트를 놓친 뒤 3을 다시 요청하면 이전 코드는 명령을 보내지 않았습니다. 합성 회귀에서 이 경로를 재현합니다. 이는 사용자 전구의 모든 실패 원인을 확정한 것은 아닙니다.

새 버전은 현재 카탈로그가 증명하는 밝기 명령을 생략하기 전 실제 기기의 같은 Location·component·capability·attribute 상태를 읽습니다. 새 조회와 현재 상태가 모두 목표와 같으면 쓰지 않고 종료합니다. 누락·다른 대상·오래된 조회·실패한 조회는 생략 근거로 쓰지 않습니다. 실제 값이 다르거나 근거가 없으면 기존 검증 경로로 한 번 전송하고 실제 확인을 기다립니다. 단순 접수를 동작 완료로 바꾸지 않습니다. 묶음 조명 제어는 기존대로 유지합니다.

명령 확인 과정의 상태 읽기는 해당 기기만 대상으로 하고, 전체 인벤토리를 반복 복제하지 않습니다. 각 반환값의 깊은 복사와 기존 카메라 필터, 다른 위치 및 오프라인 거부를 보존합니다. 이는 알고리즘의 불필요한 복제를 제거한 것이며 사용자 HA에서 측정한 응답속도 개선 수치는 아닙니다.

Bridge와 통합의 버전을 모두 1.8.21로 맞춰 재시작합니다. 기기 삭제·재등록이나 로그인 초기화는 필요하지 않습니다. 실제 전구의 동작과 HA 표시가 일치하는지는 운영 환경에서 별도로 확인해야 합니다. 사용자 로그나 인증정보는 이 문서 및 회귀 데이터에 포함하지 않습니다.
