# 조명·공기청정기 제어 보완 — 1.8.20

## 확인된 증상과 범위

사용자는 1.8.19에서 공기청정기의 `no observed switch control`, 조명의 `command_queue_timeout`, 스위치의 `command_confirmation_timeout`을 보고했습니다. 실제 전구 전원은 동작하지만 후속 밝기·색상 변경이 되지 않는다는 보고가 있었습니다.

제공된 Bridge webarchive에는 1.8.19 기동, Web native 명령 전송/접수 표식 각각 4회, 기기 상태 재조회 표식 52회가 있었습니다. 이는 표식 수이지 고유 명령 수나 성공률이 아닙니다. 기존 로그에는 요청별 대상 속성과 실제 응답의 일치 여부가 없어 모든 상태 확인 실패의 원인을 확정하지 않습니다.

## 변경

팬은 전원 버튼을 표시할 때와 실행할 때 다른 방식으로 대상을 고르던 문제를 수정합니다. 동일한 전원의 action/detail 중복은 기존 공통 toggle 선택 정책으로 처리하고 명시적인 main 컴포넌트를 우선합니다. 기기 상태·지원 기능·실제 전송이 같은 바인딩을 사용하며, 모호한 전원이나 다른 컴포넌트를 대신 실행하지 않습니다.

조명은 실제로 관측한 상태가 켜짐일 때만 밝기·색상·색온도 변경에 앞선 중복 ON을 생략합니다. 예를 들어 이미 켜진 조명의 밝기 50% 변경은 setLevel만 실행하며, 색상은 setHue/setSaturation을 각각 확인합니다. 꺼짐/알 수 없음에서는 기존 ON 확인을 유지합니다. 명령과 속성의 현재 지원 여부·값 범위 검사도 유지합니다.

Bridge는 상태 확인마다 전체 인벤토리를 복제하지 않고 해당 기기/Location/컴포넌트/기능/속성의 상태만 독립 복사해 읽습니다. 오프라인·위치 불일치·상태 순서 보호는 유지합니다. 진단은 요청 상관관계 해시, 공개 별칭, 허용된 명령/속성명, 경과 시간, 조회 횟수, 대상 상태 존재/일치 여부를 기록합니다. 원본 이름·식별자·인수·인증정보는 기록하지 않으며 로깅 실패는 명령 결과를 변경하지 않습니다.

대기열 및 확인 시간 제한은 늘리지 않습니다. 명령 자동 재전송, 실패 무시, 입력값으로 상태 덮어쓰기, 전구 기능 강제 활성화를 하지 않습니다. 따라서 응답이 실제로 불일치하는 명령의 timeout이 모두 사라진다고 보장하지 않습니다.

## 적용과 확인

Bridge 앱과 HACS 통합을 모두 **1.8.20**으로 업데이트하고 Bridge와 Home Assistant를 재시작합니다. 기존 통합·기기·엔티티 삭제나 재페어링, 로그인 데이터 초기화는 필요하지 않습니다.

먼저 켜진 조명에서 밝기를 한 번 변경한 뒤 실제 밝기와 HA 값을 대조하고, 공기청정기 전원을 한 번 조작해 확인합니다. 실패가 남으면 Bridge 로그의 같은 `device_command:op_...`에 속한 dispatch/accepted/status_read/confirmed/failed 기록으로 전송과 상태 확인을 구분할 수 있습니다. `target_0`은 해당 응답에 정확한 대상 속성이 없고, `target_matches_0`은 요청값과 일치하는 정확한 상태를 확인하지 못했음을 뜻합니다. 단순 accepted만으로 실제 기기 동작 성공을 뜻하지 않습니다.

## 회귀 검사

공통 전원 선택, 중복 항목, 다른 컴포넌트 격리, 이미 켜진 조명의 숫자/색상 제어, 미확인 전원의 기존 확인 절차, 실패 전파, 진단의 민감정보 제거, 인벤토리 복제 감소를 자동 검사합니다. 테스트는 합성 데이터 기반이며 실제 Samsung 계정이나 사용자의 실행 중인 HA에서 조작 성공을 검증한 기록이 아닙니다. 릴리스는 기존 Validate/Security 파이프라인 통과를 전제로 합니다. README와 기존 로그인·엔티티 ID·방/재실·Home Monitor·Scene/TTS·의존성·protocol 5는 변경하지 않습니다.
