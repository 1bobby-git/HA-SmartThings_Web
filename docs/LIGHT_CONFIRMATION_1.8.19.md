# 조명 상태 확인 보완 — 1.8.19

## 보고와 확인한 코드 문제

사용자 로그: `light.turn_on`에서 `command_confirmation_timeout`. 화면의 `connection lost`는 별도의 앱/HA 연결 문제일 수도 있으며, 이 메시지만으로 물리 전구가 명령을 받았는지 또는 HA가 재시작했는지를 확정하지 않습니다.

1.8.18의 명령 확인은 기본 설정에서 1초 뒤 상태를 한 번 조회하고, 이후에는 실시간 이벤트 또는 캐시만 기다립니다. 초기 응답이 이전 값이고 후속 이벤트가 없으면 나중에 바뀐 실제 상태를 놓칠 수 있습니다. 또한 같은 색상/색온도 값에 대한 모드 전환은 실제 명령을 보내지만 새 값/이벤트가 생기지 않으면 시간 초과가 발생할 수 있습니다. HA의 명령 종료 뒤에는 실시간 스트림 지연을 보완하는 로컬 상태 읽기가 없었습니다.

## 처리

기기 상태 확인에 기존의 제한된 읽기 재검사 스케줄을 사용합니다. 기본 30초/초기 1초 설정에서는 1, 2, 4, 7, 10, 15, 20, 25초에 최대 8회 조회합니다. 한 번에 하나의 조회만 진행하며 확인 종료 시 예약을 해제합니다. 초기 상태 재검사를 꺼두면 마지막 확인 구간에서 한 번만 읽습니다. 전체 인벤토리 수집이나 기기 제어를 반복하지 않습니다.

새 이벤트 없이 같은 값을 확인할 때는 POST 완료 이후 시작된 정확한 기기 상태 조회의 응답에 해당 값이 있어야 하고, 위치와 현재 캐시도 일치해야 합니다. GET 응답의 상태는 합쳐진 캐시와 별도로 보존하므로, 빠진 속성을 기존 캐시에서 빌려 확인하지 않습니다. 기기 시간과 SSE sequence는 변경하지 않습니다. 기존 상태 순서 보호 및 안정화 시간은 유지합니다.

HA는 한 번의 조명 작업이 끝날 때(일부 실패 포함) 로컬 Bridge 인벤토리를 한 번 읽습니다. 최대 3초 안에 읽지 못하면 후속 실시간 이벤트를 기다립니다. 실패했던 명령을 성공으로 바꾸지 않으며 요청값을 상태로 저장하지 않습니다. 반복 클릭의 대기 요청은 HA와 Bridge에서 10초 후 실행 전에 만료합니다. 전송 중인 명령은 취소하거나 자동 재전송하지 않습니다.

## 적용과 확인

Bridge 앱과 HACS 통합을 **1.8.19**로 업데이트하고 각각 재시작합니다. 통합이나 기존 조명을 삭제/재등록하지 않습니다. 한 번 밝기를 조절한 뒤 실제 전구와 HA 값이 함께 바뀌는지 확인합니다. 계속 실패하면 오류에 포함된 `light on`, `light level`, `light hue`, `light saturation`, `light colorTemperature` 단계와 같은 시각의 Bridge 로그를 확인합니다. 앱 전체가 연결 끊김을 보이면 HA 재시작/연결 로그도 별도로 확인해야 합니다.

검사는 지연된 상태 읽기, 이벤트 없는 같은 값, 잘못된 대상/위치/속성, 오래된 읽기와 더 최신 상태 보호, 조회 중단, 대기 만료, HA 스트림 지연과 실패 후 실제 상태 반영을 합성 데이터로 검증합니다. 사용자 계정·실기기에서 전송/동작 완료를 검증한 기록은 아닙니다.
