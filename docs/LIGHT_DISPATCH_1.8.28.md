# 조명 중복 명령 왕복 감소 — 1.8.28

## 측정에서 확인한 병목
사용자가 제공한 1.8.27 로그의 전원 켜기는 receipt 864ms, confirmed 898ms이다. on/setLevel/setColor는 receipt 2638ms, confirmed 2639ms이고, on/setLevel/setColorTemperature는 receipt 2439ms, confirmed 2807ms이다. 이 기록에서는 상태 확인 대기보다 명령 접수 구간이 길다. 전구의 물리적 변화 시각과 HA 렌더링 완료 시각을 측정한 로그는 아니다.

기존 HA는 색상 변경에도 on을 포함한다. 최신 요청 병합으로 밝기 의도가 남으면 on/setLevel/setColor 세 개가 순차 POST된다. 1.8.28은 그 순서나 정상 동작한 setColor 형태를 바꾸지 않고, 실제 관측으로 불필요함이 확인된 전원/밝기 명령만 줄인다.

## 동작
이미 켜져 있다고 관측된 속성 변경 계획에서만 정확한 기기 상태 GET을 1회 시도한다. 기존 인증 keeper의 동일 출처 경로만 사용하며, GET은 350ms 제한, 전체 최적화는 400ms 제한이다. keeper 실패 시 새 페이지/대체 HTTP 경로를 열지 않는다. 읽기 결과는 저장소나 HA에 직접 반영하지 않는다. 상태 재확인이 꺼져 있으면 사전 조회도 생략하고 기존 계획을 사용한다. 발견과 전송은 기존 기능 정의 캐시를 공유하여 첫 조작에서 같은 capability 정의를 재조회하지 않는다.

전체 요청의 명령과 인수는 사전 조회 전에 검증한다. 새로운 응답의 기기/위치/상태 키·역할·단위가 맞고, 기존 값과 새 값이 목표와 정확히 일치하며, 읽는 사이 상태 revision이 바뀌지 않았을 때만 최적화한다. 명시된 오래된 timestamp는 거부한다. timestamp 없는 GET은 기존과 같은 값의 확인에만 사용하며 다른 값으로 덮어쓰지 않는다.

| 조건 | 실제 POST |
|---|---|
| 켜져 있고 밝기도 같으며 색상 변경 | setColor |
| 켜져 있고 밝기도 같으며 색온도 변경 | setColorTemperature |
| 켜져 있고 밝기 변경 | setLevel (색상 요청 시 뒤에 setColor 유지) |
| 꺼짐/알 수 없음 | 원래 on → setLevel → setColor 순서 유지 |
| 전원만 제어 | 기존 on 또는 off 1회, 사전 조회 없음 |
| 사전 조회 실패/느림/다른 대상/변경 충돌 | 원래 전체 계획 유지 |

색상/색온도는 값이 같더라도 모드 전환의 의미가 있으므로 항상 전송한다. 전원/밝기 생략 후에도 전체 expected 상태는 그대로 확인한다. 이미 값이 맞다는 사전 조회만으로 성공 처리하지 않는다. 읽기 중 새 요청이 들어오면 이전 계획은 POST 전에 취소할 수 있으며, 이미 전송 중인 POST는 기존대로 겹치지 않는다. Home Monitor 코드는 변경하지 않았다.

## 검증
합성 전송에서 POST마다 800ms, 사전 GET 100ms를 적용해 기존 3 POST와 수정 1 POST를 같은 서비스/카탈로그/어댑터 경로로 실행했다. 기존 확인 2401ms, 수정 확인 901ms이며 차이는 1500ms이다. 이 수치는 사용자 전구의 실측 결과가 아니다. 실제 개선은 사전 조회 응답 시간과 상태 일치 여부에 따라 달라진다.

회귀 검사는 입력 전체 선검증, 최신 의도 취소, 무반응 시 timeout 유지, 정확한 값/시각/대상 비교, 일반 GET 및 POST 정책 유지, 조회 실패/지연 fallback, 색 모드 명령 유지와 미변경 저장소를 포함한다. 전원 단독 명령의 접수 RTT는 줄이지 않았으며 이를 즉시 응답으로 바꿨다고 주장하지 않는다.

## 운영 확인
Bridge와 HACS 통합을 모두 1.8.28로 올린 뒤 재시작한다. 이미 켜진 전구에서 색상만 바꿀 때 dispatch의 commands가 [setColor], skippedCommands에 on(해당하면 setLevel)이 나타나는지 확인한다. preflightMs는 사전 조회 대기이며 receipt는 실제 접수 시각이다. 원본 기기 식별자·쿠키·토큰을 로그에 출력하지 않는다.
