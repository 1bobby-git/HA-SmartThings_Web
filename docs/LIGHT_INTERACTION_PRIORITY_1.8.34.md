# 연속 조작 중 백그라운드 간섭 축소 — 1.8.34

## 실제 관측과 범위
기준은 eb6b708675da74796fb9d0c7eedb581a774dd56b (1.8.33). 새로 제공된 기록에서는 mode_batch와 한 POST 전송이 확인됐다. 완료된 요청들의 전체 시간은 774/809/844ms와 느린 끄기 1953ms였다. 느린 끄기의 queueMs는 290, 실행은 1663ms였고 해당 POST는 totalMs 1539/browserMs 717/fetchMs 713/bridgeOverheadMs 822였다. 이 차이를 삼성 서버 시간으로 설명할 수 없으며 단독 기기 물리 반응 또는 HA 화면 렌더링 시간 자체를 측정한 것도 아니다. 다른 빠른 POST들도 약 700ms이므로 그 기본 왕복 시간과 추가 지연을 구별한다.

원본 아카이브나 계정 정보는 저장소에 포함하지 않았다. 이 로그만으로 추가 지연 822ms를 어떤 함수나 디스크 작업의 실행 시간으로 확정하지 않는다. 소스에서 확인한 별도 간섭 경로를 재현하고 줄이는 변경이다. 실제 설치 버전 문자열은 원본 발췌에 없으나 이번 계측 필드/실제 batch 기록은 확인됐다.

## 남아 있던 경로
DeviceStore는 상태 이벤트 뒤 5초 타이머에서 전체 snapshot/JSON.stringify/DatabaseSync 저장을 실행한다. 명령 경로의 전역 복사를 없앤 1.8.33에서도 이 타이머는 명령이 진행 중인지 확인하지 않았다. 타이머를 이용해 호출해도 동기 연산은 같은 이벤트 루프를 막는다. 또한 .33의 새 탐색 시작 금지는 이미 시작된 상세 탐색을 중단하지 못했다. 기존 UI의 foreground 중단 경로에 Advanced 대기열은 연결되지 않았다.

## 변경과 보존 조건
현재 명령 대기열 수가 양수이거나 마지막 명령 종료 후 750ms가 지나지 않았으면 저장 타이머를 250ms씩 미룬다. 초기 5초가 지난 뒤 최대 30초까지만 미루므로 지속 제어에도 디스크 저장이 영구 정지하지 않는다. 750ms는 백그라운드 저장/탐색의 시작 조건이며 제어 요청에 sleep을 넣지 않는다. 큐는 이미 전송 중인 POST가 끝나기 전에는 superseded 호출자가 결과를 받더라도 점유 상태를 유지한다.

정상 종료는 지연 타이머를 취소하고 최신 인벤토리를 즉시 저장한다. SQLite 실패의 기존 5초 재시도와 데이터 형식은 유지한다. 강제 종료 시 마지막 디스크 저장 이후의 캐시가 소실되는 창이 최대 30초 추가될 수 있으므로 영구 저장이나 로그인 유지 개선으로 설명하지 않는다. 이 저장소는 로그인 쿠키 저장소가 아니며 재시작의 인증/상태 재검증도 그대로다.

현재 Advanced 대기열 상태를 UI 탐색 관리자에 전달해 이미 열려 있는 탐색 전용 탭만 중단한다. 종료가 늦어도 명령을 기다리게 하지 않는다. 로그인/MFA, keeper, 실제 제어 및 재인증 탭에는 적용하지 않는다. 탭이 늦게 생성되어 그 사이 제어가 끝나더라도 이전 취소 신호를 기억해 뒤늦은 탐색을 계속하지 않는다. 기존 DOM/홈모니터 foreground 큐는 그대로다.

inventory_persist_timing은 outcome(persisted/unchanged/failed), snapshotMs, writeMs, totalMs, deferredMs만 제공한다. 50ms 이상 저장이나 연기/실패 때만 로그를 남긴다. 쿠키/토큰/파일 경로/명령 인수는 포함하지 않는다. 보조 진단 예외는 저장 성공/실패에 영향을 주지 않는다.

## 검증
- 기존 .33 production에 두 회귀 검사를 적용하면 명령 중 전체 스냅샷 호출로 실패함을 재현했다. 수정 후에는 활성 명령 중 호출/쓰기 없이 실제 SSE 상태가 전달되고, 유휴/종료/최대연기 시 최신 값이 저장되는지 검사한다.
- 30초 연기 한도, 5초 기본 간격, SQLite 잠금 후 재시도, 종료 시 flush와 타이머 취소, 관측 콜백 오류를 검사한다.
- 느리게 닫히는 탐색 탭, 늦게 생성되는 취소된 탭, keeper 비삭제, 기존 명령 종료 뒤 재개를 검사한다.
- 실제 runtime HTTP→카탈로그→Advanced adapter→보호된 확인 경로에서 batch=false/true 모두 external priority의 진입/해제 및 인증 거부를 검사한다. 전송 내용/횟수와 명령 이후 확인 조건은 변경하지 않는다.
- 실제 삼성 계정이나 전구의 장기간 동작/변경 후 속도를 대신 측정한 테스트가 아니다. GitHub 전체 CI·Chromium·HAOS 시작 검증 후 릴리스한다.
