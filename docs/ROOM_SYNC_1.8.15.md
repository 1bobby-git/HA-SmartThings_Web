# 방/영역 연결 및 카운터 모델 표시 — 1.8.15

## 확인된 코드상의 원인

이전 `repair_missing_device_area`는 `area_id`가 비어 있는 기기만 보정했습니다. 한 번 잘못 지정된 영역은 올바른 방 정보가 나중에 도착해도 수정되지 않았습니다. Bridge도 Advanced의 기기 roomId/방 이름을 후속 Web 카드 응답으로 덮어쓸 수 있었습니다. 이번 수정은 이 두 경로를 다룹니다. 사용자 스크린샷은 카운터센서 카드의 `모션 센서 · 거실 · 4개 엔티티` 표시를 보여주지만 현재 SmartThings의 실제 방 이름이나 네 엔티티의 속성 전체를 증명하지는 않습니다.

## 적용 방법

Bridge 앱과 HACS 통합을 **모두 1.8.15**로 업데이트하고 Bridge와 Home Assistant를 재시작합니다. 통합 삭제·재등록, 엔티티 삭제, 로그인 프로필 초기화는 필요하지 않습니다.

Home Assistant의 **설정 → 기기 및 서비스 → SmartThings Web → 해당 통합 항목의 구성/옵션 → SmartThings 방과 기기 영역 동기화**를 켜고 저장합니다. 옵션 저장은 통합을 다시 불러옵니다. Advanced 방 목록과 기기 연결이 확인되면 현재 기기 영역을 그 방과 일치하는 HA 영역으로 맞춥니다. 예를 들어 *합성 예시*에서 원본 방이 `화장실`이고 HA 영역이 `거실`이면 `화장실`로 바뀝니다. 이는 사용자의 현재 방 이름을 추정한 예시가 아닙니다.

옵션의 기본값은 **끔**입니다. 기존 영역이 자동 생성인지 사용자가 직접 선택했는지 구별할 과거 기록이 없기 때문입니다. 켜면 해당 통합의 기존 **기기 영역**도 원본 방을 따라 덮어쓰므로 수동 기기 영역을 유지할 사용자는 끄세요. **엔티티별 영역 설정**은 이 옵션으로 덮어쓰지 않습니다. 기기 영역이 맞는데 특정 엔티티만 다른 영역에 있으면 엔티티에 별도 영역 설정이 있는지 확인하세요.

## 방 연결 규칙

- 기기 roomId와 그 방의 locationId를 검증하며, 현재 세션에서 Advanced 기기-방 연결과 Advanced 방 목록을 모두 확인한 경우에만 `roomSource: advanced`를 전달합니다. 명시적 null은 별도로 확인된 방 해제이며 동기화 모드에서는 기기 영역도 해제합니다.
- 늦게 도착한 Web 기기/방 카드가 확인된 Advanced 연결·방 이름을 덮어쓰지 않습니다. 누락, 빈 값, 잘못된 형식은 방 삭제로 해석하지 않습니다.
- HA 영역은 정확한 이름, 그다음 Unicode·공백 정규화 이름의 유일한 일치로 찾습니다. 배열 순서·부분 문자열·기기 이름·번역·숫자 ID로 추측하지 않습니다. 대응 영역이 없으면 만들고, 모호하면 변경하지 않습니다.
- 출처 없는 이전 버전/재시작 캐시는 자동 덮어쓰기 근거가 아닙니다. 세션 복구 시 확인 표식을 초기화합니다. 기기 소유 config entry가 다르거나 과거 공유 기기이면 수정하지 않습니다.
- 방 변경 반영은 새 Advanced 인벤토리 수신 시점에 이뤄집니다. 이 변경은 무한 폴링이나 SmartThings 물리 제어를 추가하지 않습니다.

## 카드 모델명과 엔티티 유형은 별개

`모션 센서`는 기기 레지스트리의 표시용 `model`에서 올 수 있습니다. 이전 구현은 `motion_sensor_1` 같은 아이콘 분류를 실제 model 정보보다 앞서 사용했습니다. 이제 실제 보고된 `mnmo`/`model`/`modelCode`를 우선하고, 없을 때 현재 `peopleCounter` 정수 상태 또는 민감하지 않은 `setPeopleCounter` 정수 명령 계약으로 인원 카운터 기능이 확인되면 `인원 카운터`라고 표시합니다. 이름에 '카운터'가 있거나 모션 아이콘이라는 이유만으로 기능을 만들지 않습니다.

| 데이터/명령 | 유지하는 HA 유형 |
|---|---|
| 실제 현재 인원수 `peopleCounter` | `sensor`, `device_class: null`, `state_class: measurement` (증가·감소 가능) |
| 인원수 설정 `setPeopleCounter` | `number` (v1.8.14 명령 전용 입력) |
| `setUpdown`, `setFreeze` | `select` (검증된 enum) |
| 배터리 숫자 상태 | `sensor`, `device_class: battery` |
| 입출입 방향 등 문자열 상태 | 문자열 sensor; 강제로 motion/occupancy로 변환하지 않음 |
| 실제 `motion` 속성 | 원래의 `binary_sensor`/motion 동작 유지 |

명령 전용 number/select의 상태 연결을 새로 추측하지 않습니다. v1.8.14의 `unknown` 현재값, `confirm: false` 접수 의미, 기존 상태 센서는 그대로입니다. 표시 모델명을 바꾸어도 기존 엔티티 도메인·unique_id·entity_id는 이 변경에서 수정하지 않습니다.

## 검증 범위와 롤백

새 검사는 응답 순서 역전, 방 이름 덮어쓰기 방지, 누락/잘못된 ID/null, location 불일치, 지연된 출처 확인, 재시작·복구, 기본 보존/명시적 동기화, 등록 캐시 갱신, 수치 sensor 분류, 모델 우선순위를 포함합니다. 실제 HA 등록 콜백을 작은 레지스트리 대역으로 실행하는 검사와 기존 전체 CI를 사용합니다. 사용자 Samsung 계정/실행 중 Home Assistant의 방과 엔티티 속성을 직접 조회하거나 수정한 것은 아닙니다.

동기화 옵션을 끄면 후속 강제 동기화를 중지합니다. 이미 변경된 HA 영역은 자동으로 이전 값으로 되돌리지 않습니다. 필요 시 HA UI에서 영역을 수정하고, 버전 롤백 시 Bridge와 통합을 함께 v1.8.14로 되돌립니다. 로그인 데이터와 엔티티는 삭제하지 않습니다.

HA 공식 계약: [기기 레지스트리](https://developers.home-assistant.io/docs/device_registry_index/), [sensor 유형](https://developers.home-assistant.io/docs/core/entity/sensor/). `DeviceEntry.suggested_area`에 의존하지 않고 `area_id`를 사용합니다.
