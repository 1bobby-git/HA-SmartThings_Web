# 로그인 유지 및 무인 복구 — 1.8.30

## 확인 범위
기준 커밋은 54749fd730e455df33198513424306602b390321 (1.8.29)이다. 이 검토는 소스와 합성 오류/실제 Chromium fixture를 대상으로 하며, 사용자 HA에 연결해 장기간 세션이 살아 있는지 측정한 결과가 아니다. 사용자 계정의 로그인 쿠키와 비밀번호를 수집하지 않는다.

## 기존 동작과 발견한 결함
전용 `/data/chromium-profile`의 persistent context, `--restore-last-session`, background throttling 방지, 정상 종료 시 context.close, 쿠키/Local Storage를 지우지 않는 캐시 정리, 5분 간격 같은 출처 GET은 기존부터 있다. 이를 유지한다.

하지만 일반 `/location` GET과 보호된 위치 조회가 하나의 12초 AbortController 예산을 공유하여 앞선 지연이 인증 확인까지 막을 수 있었다. HTTP 200인 HTML/오류 JSON도 인증 성공으로 처리했고, 실패 후 다음 주기까지 5분을 기다렸다. renderer evaluate 자체의 무응답도 외부에서 제한되지 않았다. 브라우저 시작 즉시 재시도를 소진하면 별도 복구 주기가 없었다.

## 개선과 보존 조건
일반 페이지 요청은 최대 3초, 인증 조회는 별도 최대 9초로 나눈다(기본 12초 전체 예산). JSON 컬렉션과 위치 식별자 구조를 확인하지만 응답/식별자는 밖으로 내보내지 않는다. 401/리디렉션과 권한/네트워크/서버/형식 오류를 구분한다. 보호된 조회 성공은 인증된 읽기가 가능했다는 증거이며 서버가 만료 시간을 연장했다는 보장은 아니다.

정상 주기는 5분이고 실패하면 30/60/120/240/300초로 재시도한다. 항상 하나의 같은 페이지 검사만 실행한다. 페이지 변경/닫힘의 오래된 결과는 현재 인증 상태에 적용하지 않는다. 페이지 스크립트가 걸리면 기본 13초에 외부 대기를 끝내지만, 같은 evaluate가 끝나기 전에는 추가 요청을 쌓지 않는다. 정상 브라우저의 fetch는 각 AbortController로 중단된다.

기억된 세션의 /location 복귀 후 보호된 GET이 성공하기 전까지 복구 필요 상태를 유지한다. 현재 동작하는 조명/홈모니터 제어 중에는 복구 탐색을 보류한다. socket 재연결은 기존 삼성 로그인 화면을 탐색으로 덮어쓰지 않는다. 삼성 계정 화면에서의 기존 장기 SSO 재시도 간격(15분)과 실제 사용자 인증 필요성은 유지한다.

브라우저 전체 시작이 실패하면 기존 즉시 재시도 횟수는 유지하면서 60/120/240/300초 간격으로 다음 복구 주기를 실행한다. 동시에 두 Chromium을 띄우지 않으며 같은 전용 프로필을 사용한다. 종료 시 heartbeat와 재시도를 중단한다. 프로필 삭제, 쿠키 expires 수정, 다른 프로필의 인증 가져오기, CAPTCHA/2FA 우회, 무제한 요청, 물리 장치 조작으로 로그인 유지하기는 구현하지 않는다.

## 운영 관측
Bridge 상태 페이지의 다음 항목과 동일한 health/details 값을 확인한다.

| 항목 | 의미 |
| --- | --- |
| sessionTouchCount | 현재 프로세스에서 시작한 정기 유지 검사 수 |
| sessionTouchLastOutcome | ok / failed / reauth / stale |
| sessionTouchConsecutiveFailures | 연속 일시 실패 수 |
| sessionTouchAgeMs | 마지막 정기 검사 시작 후 경과 시간 |
| sessionTouchSuccessAgeMs | 현재 브라우저에서 마지막 정기 인증 조회 성공 후 경과 시간 |

프로세스 시작 직후 아직 정기 검사를 하지 않았으면 성공 시각이 없으며 임의의 성공 시각을 만들지 않는다. 현재 구현의 최초 정기 검사는 keeper 준비 후 5분이다. 브라우저 재시작 시 이전 context의 성공 시각을 유지하지 않는다. `session_keepalive` 로그는 outcome/durationMs/consecutiveFailures/nextCheckInMs만 내보낸다. `ok`는 평생 로그인 보장이 아니다.

## 검증
회귀 검사는 HTTP 200 HTML·잘못된 JSON·401/403/429/5xx, 일반 GET 무응답 후 독립 인증 확인, 중복 evaluate 차단, 페이지 변경 결과 폐기, 실제 검증 없는 인증 복원 거부, 장치 조작 중 복구 보류, 30/60초 재시도와 정상 주기 복귀, 브라우저 무인 재시작/종료 후 중단을 포함한다.

추가 Chromium 검사는 모든 요청을 fixture로 가로채고 임시 전용 프로필을 사용한다. 서버가 내려주는 합성 세션 쿠키 갱신, 동일 프로필 재시작 후 session cookie/Local Storage 복원, 정상 검사의 탭 개수 유지, 실패 분류를 검증한다. 실제 Samsung 서버/사용자 계정/물리 장치에 대한 장기간 실측이 아니며, CI와 사용자 HA 설치를 구분한다. 기존 모든 조명·Home Monitor 회귀 검사와 보안·패키징 게이트를 통과한 뒤 릴리스한다.
