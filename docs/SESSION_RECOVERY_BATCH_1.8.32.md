# 로그인 재발 대응과 선택적 조명 묶음 전송 — 1.8.32

## 확인 범위
기준 c2793e35f9b2786c24500f0f6ec160a0e20b3115 (1.8.31). 사용자는 로그인 재발과 조명 지연을 보고했지만 새로운 로그아웃 직전 기록이나 1.8.31 preflightReason 기록은 제공하지 않았다. 이 변경의 근거는 소스에서 재현한 복구 누락과 기존 dev_200의 POST 약 0.8초, 두 순차 POST 약 1.7초 기록이다. 실제 로그아웃 원인을 삼성 서버 강제 만료나 특정 코드 결함으로 확정하지 않는다. 현재 HA 로그인 상태와 물리 전구 동작은 직접 측정하지 않았다.

## 로그인 복구
기존 보호된 읽기와 전용 Chromium 프로필은 유지한다. 현재 keeper의 Advanced 요청이 확정적인 401을 반환하면 즉시 LOGIN_REQUIRED로 전환하고 keeper 복구를 깨운다. 이전 페이지/URL에서 늦게 도착한 401은 현재 페이지에 적용하지 않으며 403·429·네트워크 오류는 로그인 거부로 간주하지 않는다. POST는 재전송하지 않는다.

이전에 보호된 인증 조회에 성공한 keeper가 삼성 계정 화면으로 이동한 경우에는 30초 유예 뒤 별도 탭에서 /location의 정상 SSO 과정을 시도한다. 같은 브라우저 프로필만 사용하고, 보호된 GET까지 성공했을 때만 새 keeper로 교체한다. 실패나 추가 인증이 필요하면 임시 탭을 닫고 원래 로그인/MFA 폼의 입력과 URL을 그대로 유지한다. 현재 페이지가 사용자 작업으로 바뀌거나 기기 제어가 시작되면 교체하지 않는다. 실패 후 5분 이내에 반복하지 않는다. 처음부터 로그인되지 않은 브라우저의 기존 15분 유예는 유지한다.

관리형 같은-URL 새로고침도 검사 세대를 변경하여 이전 응답/멈춘 promise가 이후 인증을 오염시키거나 새 검사를 영구 차단하지 않게 한다. 이미 거부된 세션은 URL만 복귀한 것으로 정상 처리하지 않는다. 서버가 모든 세션을 폐기하거나 비밀번호/추가 인증을 요구하면 사용자가 VNC에서 정상 로그인해야 한다. 쿠키 만료일 조작, 비밀번호 수집, MFA/CAPTCHA 우회, 타 계정 세션 복원은 하지 않는다.

로그: `session_authentication_rejected`는 보호된 요청에서 인증이 거부됨, `session_recovery`의 phase는 attempt/verified/login_required/failed/stale이다. 기존 `session_keepalive`의 ok는 그 검사 시점의 인증 성공이지 영구 유지를 뜻하지 않는다. 토큰·쿠키·응답 본문은 로그에 추가하지 않는다.

## 조명 묶음 모드
앱 구성에 다음 한 항목을 추가하거나 false를 true로 바꾸고 Bridge 앱을 재시작한다. 다른 설정은 삭제하지 않는다.

```yaml
light_command_batch_enabled: true
```

기본 false는 이전 정상 동작과 단일 명령 전송 순서를 보존한다. true일 때 같은 전구/컴포넌트의 검증된 on, setLevel, setColor, setColorTemperature가 여러 개면 commands 배열을 한 Advanced POST에 담는다. 별도 사전 GET을 수행하지 않고 필요한 전원 명령도 모두 포함한다. 배열 순서는 유지하지만 삼성/기기가 원자적 또는 순차로 실행함을 보장하지 않는다. 원본 capability와 인수 검증, 각 receipt 검사, 전체 목표 상태의 독립 확인을 유지한다. 불명확한 응답이나 부분 실패는 오류로 알리며 자동 순차 재전송/롤백으로 실제 기기를 중복 조작하지 않는다. 단독 on/off와 setHue/setSaturation 경로는 기존 동작을 유지한다.

`command_route:advanced:dispatch:attempt:mode_batch:commands_3`은 묶음 전송 선택, mode_sequence는 기존 개별 전송이다. 기존 request timing과 실제 상태 확인 로그도 유지한다. 해당 전구가 묶음 처리를 지원하지 않아 실패하면 false로 복귀 후 앱을 재시작한다. 이 선택 모드의 실제 사용자 전구 호환성과 속도는 아직 검증되지 않았다.

## 검증
실제 서비스·카탈로그·어댑터를 사용한 합성 검사에서 POST당 800ms를 주었을 때 세 명령의 전송을 3회에서 1회로 줄여 1600ms 차이가 발생한다. 물리 전구의 실제 개선 수치나 단일 켜기/끄기 왕복 시간 제거를 뜻하지 않는다. 접수만 되고 상태가 바뀌지 않으면 계속 시간 초과이며, 잘못된 후속 인수/취소는 POST 전에 차단하고, 부분 receipt는 재전송 없이 실패한다.

기존 로그인·홈모니터·조명 회귀 검사 외에 실제 Chromium의 모든 네트워크를 가로채는 fixture로 원래 로그인 폼 보존과 보호된 읽기 확인 후 새 탭 승격, 같은 프로필의 쿠키/localStorage 복원을 검사한다. 이 검사는 실제 삼성 계정 장기 유지 실험이 아니다. GitHub의 전체 Validate/Security·Chromium·HAOS 시작·HACS/Hassfest 성공 후 릴리스한다. Bridge와 HACS 통합의 버전은 모두 1.8.32다.
