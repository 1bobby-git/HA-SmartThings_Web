# Architecture

The limited-alpha system is a SmartThings Web observer and push-confirmed controller. A TypeScript bridge owns a Playwright persistent Chromium context, one observation-only keeper page at `https://my.smartthings.com/location`, short-lived separate command pages, network observers, redaction, normalized SQLite inventory, a private browser profile, and authenticated local HTTP/SSE routes. Device state comes from SmartThings Web Socket.IO snapshots/events plus one browser-generation bootstrap snapshot naturally loaded by the signed-in Advanced device page; DOM text and image pixels are never state sources.

The Home Assistant add-on wraps the bridge with Xvfb, Openbox, x11vnc, noVNC, nginx Ingress, and s6 supervision. The custom integration consumes the local full inventory and `/api/v1/events` stream, atomically merges inventory markers, resynchronizes on reconnect/sequence gaps, rejects stale `updatedAt` values, and exposes sensor, binary sensor, switch, light, button, number, fan, media player, climate, cover, update, event, select, scene, alarm panel, and image platforms without SmartThings polling. In 0.1.79, SmartThings Web-only values that the official integration lacks remain as diagnostic sensors; values with clear Home Assistant roles are grouped under their primary entity platforms, and raw SmartThings Web content is preserved as attributes. Its control plane adds location selection, safe-control/read-only options, local Bridge-token reauthentication, a Samsung-login Repair issue, and aggregate redacted diagnostics; it never collects Samsung credentials or session material. Synthetic refresh is not modeled unless SmartThings Web exposes a real observed button control for it.

The Advanced bootstrap is observation-only. The Bridge installs its network observer before navigating a temporary page to `https://my.smartthings.com/advanced`, accepts only same-origin full device-list responses, redacts identifiers before merge, and closes the page after the bounded initial load. Included status, health, presentation, category/type, room, and safe semantic component roles may enrich the existing inventory, but `allowedActions` never creates a control. Older or undated Advanced states cannot overwrite a newer pushed state. No periodic Advanced request, cookie replay, direct Cupcake mutation, or second authenticated client is created.

Camera handling is deliberately still-image only. Signed media URLs are observed transiently and either fetched from allowlisted HTTPS SmartThings/Samsung media hosts or correlated with the site's Socket.IO binary thumbnail ACK on the same WebSocket connection. Only bounded JPEG, PNG, or WebP bytes and non-secret metadata are persisted; signed URLs are discarded, and the image is served through the authenticated local image route.
