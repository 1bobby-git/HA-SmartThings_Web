## 로그인 유지 확인 실패 수정

- 대시보드의 DOM 요소가 8,000개를 넘으면 로그인 설정 검사를 무조건 차단하던 조건을 제거했습니다. 설정 제목과 제한된 설정창 내부에서만 대상을 탐색합니다. 기기가 많은 화면에서도 이미 켜 둔 로그인 유지 스위치를 읽고, 실제 비밀번호·인증번호·다른 모달은 계속 보호합니다.
- **실제 세션 읽기**와 **보충 갱신 가능 여부**를 분리했습니다. 갱신용 액션이나 선택적인 세션 길이 값이 아직 준비되지 않았다는 이유로 읽을 수 있는 실제 로그인 상태까지 숨기지 않습니다. 읽기 지원만으로 재인증을 허용하지는 않습니다.
- 웹 앱이 만료 시각을 제공하지 않으면 `웹 앱에서 제공하지 않음`으로 표시합니다. 만료 시각을 만들거나 무기한 로그인으로 간주하지 않습니다. 실제 세션의 로그인 유지 ON과 현재 Location의 보호된 읽기가 확인되어야 정상으로 표시합니다. 인증 거절은 계속 로그인 필요로 처리합니다.
- 늦게 초기화되는 모듈 내보내기를 다시 확인하고, 순환 참조로 형제 내보내기 하나를 읽지 못해도 정상 저장소를 놓치지 않도록 수정했습니다. 임의의 모듈 실행이나 쿠키·Redux 상태 직접 수정은 하지 않습니다.
- 관찰기 없음, 상태 저장소 연결 대기, 설정값·소켓 준비 대기, 세션 형식 확인 필요, 읽기는 가능하지만 보충 갱신 기능은 확인 불가인 상황을 한글로 구분합니다. 확인 실패를 설정 OFF나 로그아웃으로 표시하지 않습니다.
- 기존 정상 탭 보존, 네이티브 인증 결과 검증, 중복 갱신 방지, 명령 처리 중 보류, noVNC·페어링·기기 ID와 쉐도우 없는 작은 radius 디자인을 유지합니다.

### 적용

SmartThings Web Bridge 앱을 **1.8.54**로 업데이트한 뒤 브릿지 웹페이지를 새로고침하세요. 브릿지 내부 브라우저(noVNC)의 `로그인 유지`가 이미 켜져 있다면 그대로 두세요. 설정 초기화·프로필 삭제·로그아웃은 필요하지 않습니다. 상태가 준비된 후 `상태 다시 확인`으로 실제 검사를 요청할 수 있습니다.

### 검증 범위

기존 버전과 수정 버전에서 20,000개 요소의 대시보드와 로그인 설정창을 비교해 기존의 읽기 실패를 재현했습니다. 확보한 SmartThings Web 2.57.0의 실제 번들 초기화·상태 저장소에 가상 세션을 넣어 선택적 설정값 누락 시의 차이도 확인했습니다. 자동 검증은 외부 계정 통신을 차단한 Chromium 및 단위 테스트이며, 사용자 계정의 현재 상태나 8/24시간 연속 로그인 유지가 검증되었다는 의미는 아닙니다. 서버가 요구하는 재인증은 우회하지 않습니다.
