로그인과 명령 접수는 정상인데 단일 스위치가 실제로 켜지지 않는 전송 경로를 보완합니다.

- 1.8.58에서 단일 `switch.on/off`가 웹 앱의 `api/device` 서비스를 우선 사용하도록 했지만, 런타임 클라이언트 심볼 포착이 누락되면 기존 Advanced POST로 내려갈 수 있었습니다.
- 시작 시 `api/device`를 참조하는 자연 실행 모듈의 export에서 실제 `service()` 클라이언트가 확인되면 캡처하고, 명령 직전에도 심볼이 없으면 이미 로드된 SmartThings webpack 모듈 캐시의 export만 제한적으로 검사해 다시 찾습니다. 모듈을 새로 require하거나 실행하지 않습니다.
- 복구된 클라이언트는 기존과 동일하게 정확한 대상의 `api/device.patch(... execute: true ...)` 경로만 사용하고, patch가 시작된 뒤 오류나 시간 초과에는 다른 전송 경로로 재전송하지 않습니다.
- 런타임 캐시에서 클라이언트를 복구한 경우 Advanced fetch를 사용하지 않는 회귀 검사를 추가했습니다. 실제 성공 판정은 계속 최신 기기 상태 확인을 요구합니다.

Bridge 앱과 HACS 통합 버전은 1.8.59입니다. 자동 회귀 검사는 실제 물리 기기의 동작 확인을 대신하지 않습니다.
