# 1.8.64

Bridge 데이터가 초기화된 뒤 Home Assistant 엔티티가 다른 장치를 가리킬 수 있던 문제를 막습니다.

- **장치·위치 별칭:** 새로 찾은 장치와 위치의 별칭을 SmartThings ID의 단방향 해시로 만듭니다(`dev_` 또는 `loc_` 뒤 숫자 20자리). 애드온을 다시 설치해 Bridge 데이터가 비어도 같은 장치는 같은 별칭을 다시 받습니다. 지금까지는 빈 데이터에서 `dev_001`부터 순번을 다시 매겨, 재설치 뒤 기존 엔티티가 다른 장치를 가리킬 수 있었습니다.
- **기존 별칭 유지:** 1.8.63 이하에서 만든 별칭(`dev_001` 등)은 그대로 씁니다. 지금 쓰는 엔티티와 자동화는 바뀌지 않습니다.
- **위치를 잃었을 때:** Bridge가 이 항목의 위치를 더 이상 보고하지 않으면(데이터 초기화, 다른 Samsung 계정 로그인) 기기와 엔티티를 지우지 않고 설정을 멈춘 뒤 복구 알림을 띄웁니다.
- **설정 오류 안내:** Bridge 주소 형식이 잘못되면 "알 수 없는 오류" 대신 로컬 http(s) 주소를 입력하라고 안내합니다.
- **이벤트 스트림:** 너무 긴 줄이 와도 오류 기록 없이 다시 연결합니다.
- **보안 신고 안내:** SECURITY.md에서 외부 신고자가 할 수 없는 "보안 권고 초안 만들기" 대신, 세부 내용 없이 연락을 요청하는 방법을 안내합니다.

## 업데이트할 때

- 애드온과 통합을 함께 1.8.64로 올리세요. 다른 설정은 필요 없습니다.
- 1.8.63 이하에서 쓰던 애드온을 지우고 다시 설치하면 예전 순번 별칭은 되살릴 수 없습니다. 이때 Home Assistant는 엔티티를 다른 장치에 붙이지 않고 복구 알림을 띄웁니다. 알림에 따라 통합 항목을 삭제한 뒤 위치를 다시 추가하세요. 1.8.64부터 만든 별칭은 재설치 뒤에도 그대로 돌아옵니다.

기기 명령, 인증 정보, 페어링 방식은 바뀌지 않습니다.
